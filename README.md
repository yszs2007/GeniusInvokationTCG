# 原神七圣召唤 · 卡牌对战系统（GeniusInvokationTCG）

基于 **C++17 + Qt 6 Widgets** 实现的图形化回合制卡牌对战游戏，完整复刻《原神》七圣召唤的核心玩法：掷骰、出牌、切人、放技能、算元素反应、打 AI，一局到底。

> 高级语言程序设计课程大作业 · 南开大学 计算机大类（伯苓班）

---

## 功能特性

- **完整对局流程**：选择背景 → 选择出战角色 → 掷骰 → 行动 → 回合结算 → 胜负判定 → 重新开始
- **8 枚元素骰**：风 / 岩 / 雷 / 草 / 水 / 火 / 冰 / 万能，支持一次性重投
- **14 名可玩角色**：芭芭拉、班尼特、重云、迪卢克、菲谢尔、凯亚、卡维、柯莱、刻晴、凝光、珊瑚宫心海、砂糖、温迪、钟离，每人独立立绘与技能
- **三种技能**：普通攻击 **A** / 元素战技 **E** / 元素爆发 **Q**，按技能类型与卡牌费用校验骰子是否足够
- **8 种元素反应**：蒸发、融化、冻结、感电、激化、绽放、扩散、结晶，自动判定并结算增伤 / 冻结 / 感电等效果
- **15 张行动牌**：武器牌（旅行剑、白缨枪、白铁大剑、鸦羽弓…）、支援牌（西风大教堂、望舒客栈、骑士团图书馆…）、事件牌（交给我吧、换班时间、星天之兆…）、料理牌（甜甜花酿鸡、蒙德土豆饼…），开局发 5 张并可换牌
- **7 种召唤物**：暴风之眼、大型风灵、岩脊、璇玑屏、奥兹、柯里安巴、化海月，带持续回合倒计时，每回合结算伤害 / 治疗
- **持续效果牌**：西风大教堂、望舒客栈，按回合倒计时生效
- **敌方 AI**：我方结束回合后，AI 自动连续执行 3 次行动
- **阵亡与胜负**：出战角色阵亡自动切换后台血量最高的存活角色；全员阵亡判负，敌方全灭判胜；结算弹窗可一键重新开始
- **界面细节**：动态卡面、骰子选中高亮、伤害日志、状态栏、弹窗置顶（`raise()`）与事件过滤

## 玩法流程

```
背景选择 ──▶ 角色选择（三人队）──▶ 掷骰（8 枚，可重投一次）
                                      │
                                      ▼
                        行动阶段：打牌 / 切换角色 / A · E · Q
                                      │
                                结束回合 ──▶ 敌方 AI 连续行动 3 次
                                      │
                          元素反应 · 召唤物 · 支援牌结算
                                      │
                          阵亡判定 ──▶ 胜负结算 ──▶ 重新开始
```

## 环境与构建

| 项 | 版本 |
| --- | --- |
| 操作系统 | Windows 11 |
| 开发工具 | Qt Creator 19 |
| 图形框架 | Qt 6（Widgets） |
| 语言标准 | C++17 |
| 构建系统 | CMake ≥ 3.16 |

```bash
# 1. 克隆
git clone https://github.com/yszs2007/GeniusInvokationTCG.git
cd GeniusInvokationTCG

# 2. 配置（把 Qt 路径换成本机安装位置）
cmake -S . -B build -DCMAKE_PREFIX_PATH="C:/Qt/6.8.3/mingw_64"

# 3. 编译
cmake --build build --config Release

# 也可直接用 Qt Creator 打开 CMakeLists.txt 运行
```

> 使用 `Qt6::Widgets` 单一模块，`AUTOMOC` / `AUTOUIC` / `AUTORCC` 全开，`res.qrc` 打包全部图片资源，编译产物为独立 exe（`WIN32_EXECUTABLE`）。

## 设计要点

- **面向对象建模**：`Card` 抽象基类派生 `RoleCard` / `ActionCard`，角色、卡牌、技能、召唤物各自成类，`QVector<RoleCard*>` 统一管理队伍。
- **回合状态机**：以 `GamePhase` + `isPlayerActionPhase`、`myTurnEnded`、`enemyTurnEnded`、`enemyActionTimes` 等标记严格约束行动顺序，杜绝双方同时行动。
- **事件分发**：重写 `eventFilter` 处理骰子点击与卡牌选中，配合 `raise()` 解决控件层级遮挡。
- **数据驱动 UI**：卡面、立绘、骰子贴图全部走 `res.qrc`，按枚举值（`RoleID`、`ElementType`）拼路径加载。
